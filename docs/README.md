## 관리 방식

- 리서치는 `research/YYYY-MM-DD-topic.md`에 저장하고 이 목록에 연결한다.
- 제품 방향과 인터뷰는 `product/`에 저장하며, 사용자가 설명한 목표와 설계 제안·미정 사항을 구분한다.
- 이전 맥락은 `context/`에 보관한다. 원본 인계 자료의 상태·경로·시점 표기는 당시 기록으로 읽으며, 현재 요구나 실행 지침은 최신 문서에서 확인한다.
- 문서에 조사일, 범위, 결론, 근거 링크, 한계, 후속 확인 사항을 남긴다.
- 출처에서 확인한 사실, 공급자의 측정·주장, 조사자의 해석과 제안을 구분한다.
- 내용 보완 시 기존 문서의 갱신 이력과 목록 상태를 수정한다. 결론이 바뀌면 이전 판단과 바뀐 이유를 남긴다.
- 리서치의 설계 제안은 제품 요구사항이나 개발 착수 결정으로 자동 확정하지 않는다.
