# Windows 데스크톱 앱

SiloLink의 첫 네이티브 데스크톱이다. 사용자 선택인 ‘발견에서 시작’ 배치를 제공된 브랜드 자산과 함께 구현한다. Tauri 2·React·TypeScript 화면이 공통 Rust 라이브러리를 직접 사용한다. CLI 출력을 파싱하거나 기존 CLI 로직을 JavaScript로 옮기지 않는다.

## 실행과 빌드

Windows x64·MSVC·WebView2를 기준으로 확인한다. 소스 개발에는 Node 22.20 이상과 Rust 1.90 MSVC, C++ Build Tools가 필요하다. 실행 파일에는 Node/npm/Python 런타임을 포함하거나 요구하지 않는다. WebView2는 Windows 시스템 런타임을 사용한다. [Tauri Windows 요구사항](https://v2.tauri.app/start/prerequisites/), [화면과 Rust 명령](https://v2.tauri.app/develop/calling-rust/).

```powershell
# 저장소 루트
.\scripts\desktop.ps1 -Mode dev

# 프로덕션 실행 파일 + Windows 설치 프로그램
.\scripts\desktop.ps1 -Mode build

# 실행 파일만 빌드
.\scripts\desktop.ps1 -Mode build -NoBundle
```

스크립트는 기존 저장소의 로컬 MSVC 도구체인이 있으면 그것을 사용하고, 종료 후 환경 변수를 복구한다. 프런트엔드 의존성은 `desktop/package-lock.json`, Rust 의존성은 루트 `Cargo.lock`으로 고정한다. 루트 Cargo의 기본 대상은 기존 CLI로 유지한다.

실행 파일은 `target/release/silolink-desktop.exe`, NSIS 설치 프로그램은 `target/release/bundle/nsis/`에 생성된다. 설치 프로그램을 빌드하는 것과 사용자 PC에 실제 설치하는 것은 구별한다. 자동 업데이트·macOS 배포는 현재 제공하지 않는다. 코드 서명은 아직 적용하지 않으며, SignPath 승인 후 태그 릴리스에서 처리한다([배포 문서](releasing.md#코드-서명)).

데스크톱 스크립트는 먼저 `prepare-desktop.ps1`로 CLI를 빌드하고 Tauri 리소스로 준비한다. 설치 프로그램에 `bin/silolink.exe`가 포함된다. 개발자가 Cargo로 앱을 직접 검사할 때도 먼저 `.\scripts\prepare-desktop.ps1 -Profile debug`를 실행한다. 앱 EXE만 다른 폴더로 복사하면 이 리소스가 누락되므로 설치 프로그램을 사용하거나 `bin`도 함께 보존한다.

실행 중인 앱을 보존하며 별도 체험 빌드를 만들 때는 `CARGO_TARGET_DIR`로 출력 경로를 바꾸고 `-ConfigPath <JSON>`으로 Tauri 설정을 덮어쓸 수 있다. 별도 `identifier`와 `productName`을 사용하면 기존 앱과 설정·단일 실행 제한이 분리된다. `ConfigPath`는 작업 디렉터리를 바꾸기 전에 실제 경로로 해석한다.

## 첫 사용

### 디자인 코멘트용 브라우저 미리보기

데스크톱을 설치하지 않고 같은 React 화면을 검토하려면 `desktop`에서 `npm run design`을 실행하고 `http://127.0.0.1:7431/design.html`을 내장 브라우저로 연다. 기본 주소 `/`와 `/index.html`도 이 리뷰 화면으로 이동한다. 브라우저의 Annotate에서 요소 또는 영역을 선택해 코멘트를 저장한 뒤 채팅으로 보내 수정 요청을 전달한다.

상단의 디자인 미리보기 표시에서 예시 데이터/첫 사용 화면과 밝음/어두움 테마를 바꾼다. 메뉴·탭·프로젝트 전환·예시 문서 읽기/검색과 노트 보고서 미리보기를 제공한다. 파일 쓰기·수집·스킬 등록·AI 실행은 성공 응답 대신 미리보기 안내를 표시한다. 예시 데이터는 브라우저 메모리에만 있으며 사용자 파일을 읽거나 저장하지 않는다.

`vite.design.config.mjs`에서만 API와 이벤트를 `src/design-preview`로 연결한다. 일반 `npm run dev`, 프로덕션 빌드와 Tauri 명령의 계약은 유지한다. 일반 브라우저 실행은 계속 `DESKTOP_REQUIRED`를 반환하고, 프로덕션 번들에는 예시 데이터와 리뷰 도구 모음을 넣지 않는다. 실행 중인 디자인 서버의 화면 검사는 `desktop/tests/design_preview.py`로 수행한다. Annotate에서 주석 저장→채팅 전달은 내장 브라우저에서 사용자가 확인한다.

### 실제 앱 시작

1. 앱의 ‘프로젝트 연결’에서 폴더를 선택하고 관리 정보 생성 안내를 읽은 뒤 연결한다. 연결 버튼이 공통 init을 명시적으로 요청한다. 초기화 체크박스나 명령어 입력은 요구하지 않는다. 스킬로 이미 연결한 폴더도 같은 프로젝트로 열린다.
2. 새로 연결한 프로젝트를 선택하고 ‘첫 문서 확인’에서 문서 개수·정리 후보·경고를 본다. 원문 목록과 후보 원문으로 바로 이동한다. 문서 0개와 읽기 실패는 구별한다. 이 단계는 기록 보관 위치 없이 동작한다.
3. AI 기록도 원하면 ‘AI 기록 가져오기’ 탭에서 ‘AI 기록 수집 켜기’를 누른다. 연결된 프로젝트의 첫 수집을 바로 시작하고 이후 설정한 간격으로 수집한다. ‘AI 대화 기록 가져오기’로 선택한 프로젝트만 한 번 가져올 수도 있다. 현재 수집 범위에서 도구별 결과와 마지막 반영을 확인한다.
4. 사용 분석·대화·조사·학습·작업·회고 등 필요한 지점에서 이어간다. 고정 순서를 요구하지 않는다.

## AI 도구의 스킬 연결

첫 화면의 ‘AI 도구 연결’ 또는 하단 설정 아이콘의 ‘AI 도구’ 분류에서 Codex·Claude Code·Antigravity의 사용자 스킬을 등록한다. 설정은 AI 도구·화면·기록·수집·알림·회고·앱 관리 분류에서 선택하며, 분류 사이의 입력 초안을 유지한 채 기존 저장 명령으로 함께 반영한다. `tool_connections`는 기존 공통 설치 계약을 읽기 전용으로 검사하며, `connect_tool`은 세 호스트만 허용하고 기존 `install::setup`을 호출한다. 설치 파일의 리소스 경로와 OS 사용자 홈은 네이티브에서 결정하며 화면은 임의 실행 파일·저장 경로를 전달하지 않는다. `SILOLINK_USER_HOME`은 기존 CLI와 같은 격리 검증용 홈 재정의다.

등록 상태는 스킬·메타데이터와 실제 동봉 CLI 경로를 대조한다. 원문이 수정됐거나 다른 설치를 가리키거나 링크를 발견하면 ‘기존 스킬 확인 필요’로 표시하고 보존한다. 이미 동일하게 등록됐다면 재실행을 유지한다. 호스트 프로그램 설치·로그인 성공이나 Antigravity 실제 실행을 ‘연결됨’에 포함하지 않는다.

자동 빌드와 태그 배포는 [배포 안내](releasing.md)를 참고한다.

연결 버튼은 통합 스킬과 기능별 스킬 10개를 함께 설치한다. 기존 통합 스킬만 있는 정상 설치에는 ‘기능별 스킬 추가 가능’과 ‘스킬 업데이트’를 제공한다. 상태 조회는 11개 전체를 검사하고, 사용자 수정이나 동명 타사 항목이 있으면 새 스킬 추가도 중단해 기존 파일을 보존한다. Codex용 플러그인 ZIP도 같은 스킬과 한국어 `agents/openai.yaml`을 포함한다.

## 데이터와 코어의 경계

- 앱의 프로젝트 목록·설정·노트·출처·작업·대화·알림은 Tauri app_config_dir 아래 `workspace.json`에 저장한다. 완성한 파일을 교체한 뒤 메모리 상태를 갱신한다. 지원하지 않는 버전·잘못된 JSON은 보존하고 오류로 알린다.
- 기록의 `silolink.sqlite`와 문서 변경의 `document-changes.sqlite`는 첫 쓰기 때 기본 로컬 폴더 `%LOCALAPPDATA%\io.silolink.desktop\Data`에 저장한다. 별도 앱 식별자로 빌드하면 해당 식별자 아래에 저장한다. ‘설정 → 기록·수집’에서 기존 CLI의 state-dir 같은 별도 경로를 선택하거나 기본 위치로 돌아갈 수 있다. 위치를 바꾸면 해당 경로의 데이터를 사용하며 기존 파일은 각 폴더에 보존한다.
- 프로젝트는 경로와 ID를 재확인한다. 문서 본문은 코어의 스캔 범위·링크 제외·크기·UTF-8·revision 검사를 거친다.
- 수정·새 문서·삭제를 본문 중심으로 작성하거나 외부 JSON 변경안을 가져올 수 있다. 현재 앱에서 검사한 불변 계획만 반영하고, 실제 충돌·부분 결과·링크 검사·복구는 공통 코어가 결정한다.
- 외부 링크는 네이티브 경계에서 HTTP/HTTPS·호스트·내장 자격증명 여부를 검사한다. Markdown 원문 HTML을 실행하지 않으며 임의 파일 API나 셸 실행 API를 화면에 노출하지 않는다.
- `SILOLINK_DESKTOP_CONFIG_DIR`은 독립적인 검증 프로필에 사용한다. 이때 기본 저장 위치는 프로필의 `Data` 하위 폴더다. 일반 사용자 실행에서는 설정하지 않는다.

## AI 실행과 분석

조사는 자료/조사 노트 탭에서 시작하고 목록을 선택해 상세를 연다. 학습은 노트 목록에서 ‘학습 주제 추가’로 작성 화면을 연다. 저장·계획 등 주요 실행은 관련 영역 하단 오른쪽에 둔다. ‘노트 내보내기’는 요청했을 때만 선택 목록을 열며 조사·학습·규칙 화면의 해당 종류로 범위를 제한한다. 저장·내보내기 네이티브 명령은 기존 프로젝트와 노트 ID 검사를 유지한다.

사이드바의 대화 메뉴에서 질문을 작성하고 AI 도구를 선택한다. 문서·기록·다른 프로젝트는 ‘자료 선택’을 열어 고르고, 접힌 상태에서도 포함할 자료 수를 확인한다. ‘문서 요약’ 예시는 현재 선택 범위의 문서 최대 20개와 질문 초안을 채우며, 실제 실행은 ‘질문하기’를 눌렀을 때 시작한다. 새 대화는 이 화면 안에서 시작하고 이전 대화는 아래 목록에서 연다.

로컬 집계는 실제 사용자 요청만 대상으로 한 문장 일치·표현 후보다. 의미 분석·학습·지식 연결·구조 비교·계획은 사용자가 대화 실행을 요청할 때 기존 공식 Codex/Claude Code CLI를 호출한다. 별도의 로그인·토큰 중계를 만들지 않는다.

- 질문·프로젝트·선택한 기록/문서/출처와 이전 대화 맥락을 보존한다. 문서 revision이 바뀌었거나 자료가 64 KB 한도를 넘으면 조용히 잘라 보내지 않고 범위 조정을 요청한다.
- Codex는 읽기 전용 프로젝트 모드, Claude는 파일 도구 없이 실행한다. 대화가 실제 문서를 바로 수정하는 경로로 동작하지 않는다.
- 입력 질문 16 KB, 응답 8 MB, 실행 240초 상한을 적용한다. 종료·실패·취소·중간 종료를 구별하고 이미 보존한 사용자 요청을 유지한다.
- 중지는 해당 자식 프로세스를 종료한다. 앱 완전 종료 전에도 진행 중 요청에 취소를 전달한다.
- CLI 설치·로그인·구독/이용 한도·지원 플래그가 맞아야 실제 모델 응답을 받을 수 있다. 현재 PC의 명령 도움말과 검증용 프로세스로 연결을 확인하며, 검증용 응답을 실제 모델 품질 검증으로 주장하지 않는다.
- 출처는 직접 작성하거나 URL에서 원문을 가져와 등록한다. 자동 웹 검색과 사용자의 원문 확인은 각각 별도 상태로 다룬다.

## 백그라운드와 회고

기본값은 백그라운드 수집과 시스템 알림이 꺼진 상태다. 수집을 켜면 연결된 프로젝트를 바로 순차 수집한다. 이후에는 설정한 간격을 따르며 창을 닫으면 트레이에 남는다. 같은 반복 발견과 같은 날짜의 회고 알림은 식별자로 중복 방지한다. 완전 종료는 트레이나 설정 화면에서 선택한다.

일간·최근 7일은 실제 `occurredAt`과 선택한 시간대 기준으로 집계한다. 시각 근거가 없는 기록은 기간 집계에서 제외하고 누락 수를 드러낸다. 시스템이 완전 종료된 동안의 상시 수집·OS 자동 시작을 구현했다고 보지 않는다.

## 시간과 계획

본인 작업은 시작/중지한 구간으로 기록한다. 작업 관점은 사용자 입력이며 단계 순서를 강제하지 않는다. 겹치는 본인 구간은 합집합으로 계산하고 AI 요청의 경과와 단순 합산하지 않는다. AI 내부 실행·대기는 아직 분리 계측하지 않아 요청 경과를 실행 시간으로 표시하지 않는다. 작업 완료와 사용자 확인은 독립적으로 남긴다. 기록이 부족한 예상은 확정 기간으로 채우지 않는다.

## 0.2.0의 검색·계획·공유·원문 수집

- 문서 질문은 프로젝트 ID·경로·리비전을 초기 선택으로 전달한다. 원문 읽기와 AI 문맥 준비가 기존 리비전 검사를 사용한다. 자동 제목은 UTF-8 240바이트 계약에 맞춰 생성하며 노트와 후속 작업에서 공유한다.
- `search_documents`는 기존 문서 스캔의 제외 규칙·UTF-8·크기·순회 제한을 사용한다. 제목·경로·본문을 검색하고 일치 구절·행·리비전을 반환한다. 정규화 본문 캐시는 한 프로젝트에 한정하고 리비전 변경과 제외·삭제를 반영한다. 결과는 최대 200개이며 부분 조회·상한을 표시한다. 검색 버튼으로 실행한다.
- 계획 화면에서 다른 프로젝트의 작업을 선택한다. `start_chat.taskIds`는 기본값이 빈 목록인 선택 필드다. 네이티브에서 선택 프로젝트에 속한 실제 저장 작업을 읽어 맥락에 포함하며 누락·다른 프로젝트 범위의 ID는 거부한다.
- 조사·학습·규칙 화면의 내보내기는 선택한 프로젝트의 노트 ID만 검증해 미리보기와 파일 저장에 사용한다. 보고서에 노트 본문·종류·작성 시점·연결 원문 ID를 포함한다. 기본 Windows 저장 대화상자로 목적지를 선택하며 임시 파일 작성 후 교체한다. 선택 취소는 파일을 만들지 않는다.
- `fetch_reference`는 공개 HTTPS의 UTF-8 HTML·텍스트만 가져온다. 응답 2 MB·추출 본문 100 KB·전체 30초·최대 3회 리디렉션 제한을 적용한다. 매 목적지의 DNS 주소를 확인하고 해당 주소로 연결을 고정하며 내부 주소·내장 인증정보를 거부한다. HTML 파서로 본문을 추출하고 스크립트·스타일·탐색 요소를 제거한다. 프록시·쿠키·로그인을 사용하지 않는 공개 자료 수집이다.
- 출처의 선택적 `fetched`에 본문·최종 URL·제목·수집 시점을 보관한다. 기존 출처는 이 필드 없이 계속 읽힌다. 가져오기만으로 `verified`를 켜지 않으며 사용자가 내용을 확인한 뒤 표시한다. 저장한 본문도 AI 문맥의 64 KB 한도에 포함된다.
- 실패한 대화는 공통 한국어 오류 안내를 표시하며 저장된 질문·이전 맥락으로 재시도할 수 있다.

## 한 사이클: 발견에서 반영까지

수집한 기록에서 시작해 실제 프로젝트 변경과 공유까지 한 흐름으로 이어진다. 각 단계는 앞 단계의 근거를 들고 간다.

| 단계 | 구현 | 근거·한계 표시 |
| --- | --- | --- |
| 요청 정제 (R02) | `src/desktop/analysis.rs`의 `request_view`가 Codex 하위 에이전트·승인 검토 프롬프트, Claude 명령·시스템 알림을 도구가 넣은 메시지로 분리하고, 첨부·브라우저 코멘트 래퍼에서는 사용자가 쓴 요청과 코멘트만 꺼낸다. 원본 기록은 바꾸지 않는다. | 제외한 건수를 사용 분석·정리서에 표시 |
| 앱 내 발견 (R03) | 글자 2-gram 유사도로 같거나 비슷한 요청을 묶고, 세 번 이상 반복되면 모델 없이 발견으로 만든다. 근거가 사라진 미검토 발견은 정리한다. | 모든 근거 원문을 인용, ‘기록에서 확인’ |
| AI 분석 (R03) | ‘AI 분석 실행’이 최근 사용자 요청(최대 160개·48 KB)을 짧은 별칭과 함께 공식 CLI에 보낸다. 응답의 각 발견은 목록에 있는 요청을 인용해야 남고, 인용문이 원문에 없으면 원문 일부로 바꾼다. | 근거 없는 발견은 제외하고 개수를 표시, ‘해석·추정’ 구별 |
| 검토 (R03-D) | 발견마다 타당함·제외·해석 수정을 남긴다. 제외한 발견은 같은 근거로 다시 알리지 않는다. | 수정한 해석을 원문과 따로 보관 |
| 알림·회고 (R06) | 새 발견은 앱 알림으로 남고, ‘발견 즉시 알림’을 켜면 Windows 알림도 보낸다. ‘수집 후 자동 AI 분석’은 새 요청 5개 이상일 때 최대 6시간에 한 번 실행한다(기본 꺼짐). 회고에 기간의 발견과 끝낸 작업이 나온다. | 자동 분석은 사용자의 CLI 이용 한도를 쓴다고 안내 |
| 후속 (R04·R07·R09) | 발견에서 학습 카드·조사·규칙 초안·작업으로 이어 가며, 저장한 노트와 작업은 발견을 `originId`로 가리킨다. 학습 노트는 정리 중·적용 중·정리됨·보류 상태를 가진다. | 발견의 후속 목록에 연결 |
| 공통·로컬 규칙 (R08) | AGENTS.md·CLAUDE.md 등 규칙 문서의 목록 항목을 프로젝트 사이에서 공통·표현이 다름·한 프로젝트에만으로 나눈다. 비교 결과나 규칙 노트에서 고른 규칙을 문서 끝 섹션으로 추가하는 변경안을 만들고, 기존 변경안 검토·반영·복구 절차로 넘긴다. | 비슷함은 후보이며 자동 병합하지 않음 |
| 실적 기반 예상 (R09) | 타이머로 측정하고 끝낸 비슷한 작업(제목 유사도+같은 관점)으로 범위와 중앙값을 낸다. 근거가 바뀔 때만 예상 이력을 남긴다. | 비교할 작업이 없으면 예상하지 않음, 근거 1개는 참고용 |
| 정리서 (R10) | 회고 화면에서 문서 현황·확인한 발견·결정/규칙/학습·조사 근거·작업 실적을 Markdown으로 미리 보고 저장한다. | 검토하지 않은 발견은 제외, 범위와 한계 절 포함 |

### Markdown 표시 계약

문서·노트·대화는 같은 `MarkdownContent`를 사용한다. 기본 CommonMark 렌더러에 [remark-gfm](https://github.com/remarkjs/remark-gfm)을 연결하고, 제목은 [rehype-slug](https://github.com/rehypejs/rehype-slug)로 GitHub 방식의 한글·중복 제목 ID를 생성한다.

| 분석한 사례 | 원인 | 현재 처리 |
| --- | --- | --- |
| 파이프 표가 한 문단으로 표시됨 | 기본 CommonMark에 GFM 표 확장이 없음 | 표·정렬·강조·이스케이프 파이프를 해석. 넓은 표는 키보드로 접근 가능한 영역 안에서 가로 스크롤 |
| `[x]`, `~~취소선~~`, 일반 URL, 각주가 원문으로 남음 | 같은 GFM 확장 누락 | 읽기 전용 체크 상태·취소선·자동 링크·각주 렌더링. 외부 URL은 사용자가 눌렀을 때 기존 네이티브 열기 기능 사용 |
| 목차·각주가 문서를 다시 읽거나 이동하지 않음 | 모든 상대 링크를 파일 링크로만 취급 | 같은 본문에서 제목·각주·돌아가기 이동. 다른 문서의 `#제목`도 읽기 완료 후 이동. 각 본문의 ID를 분리해 대화 여러 개가 있어도 충돌 방지 |
| 긴 코드·열이 많은 표가 레이아웃을 밀어냄 | 가로 오버플로 처리와 본문/앱 표 스타일의 구분 부족 | 본문 표를 앱 데이터 표와 분리. 표/코드 내부에서 가로 스크롤하고 인라인 코드·인용문을 구분 |
| HTML·이미지·알 수 없는 코드 언어 | 실행·원격 로드 기능과 Markdown 표시 기능은 별개 | HTML은 활성 DOM으로 해석하지 않고 이미지는 기존 설명 표시 유지. Mermaid·수식 전용 엔진은 추가하지 않아 코드/원문으로 읽을 수 있음 |

문서 원문을 다시 쓰거나 체크 목록 클릭으로 파일을 수정하지 않는다. 실패 재현과 코드·HTML 격리, 상대 문서 링크 회귀는 `desktop/src/markdown.test.tsx`에서 검사한다. 실제 창에서 표 정렬·가로 스크롤·제목/각주 이동·문서 간 앵커·테마를 확인하는 픽스처는 `desktop/tests/fixtures/markdown.md`이며 `native_smoke.py`에 포함한다.

### 실행 명령

```powershell
.\scripts\cargo.ps1 -CargoArguments @('test', '--all-targets', '--locked')
.\scripts\cargo.ps1 -CargoArguments @('test', '-p', 'silolink-desktop', '--lib', '--locked')
.\scripts\cargo.ps1 -CargoArguments @('clippy', '--workspace', '--all-targets', '--locked', '--', '-D', 'warnings')

Set-Location desktop
npm ci
npm run build
npm test
```

`desktop/tests/native_smoke.py`는 빌드한 실제 WebView2 앱과 Rust IPC를 사용한다. Python/Playwright가 있는 개발 환경에서 실행한다. 독립적인 `.tools/desktop-smoke/<UUID>` 프로필과 임시 프로젝트, 검증용 CLI 프로세스를 사용해 사용자 프로젝트·로그인·실제 모델을 호출하지 않는다. 로고(1320px·1040px 창의 밝은·어두운 테마와 사이드바 정렬)·초기화·수집·읽기·Markdown 링크·표현 집계·학습/작업·변경/충돌/복구·공급자 전환/실패/취소·재시작 저장을 확인한다.

실행 전 `cargo build -p silolink-desktop --features custom-protocol --bins --locked`로 개발 실행 파일과 검증용 공급자를 빌드한다. 기본 검증은 개발 실행 파일을 사용하고, `python desktop/tests/native_smoke.py --executable target/release/silolink-desktop.exe`로 배포용 실행 파일도 검사할 수 있다. 앱의 작업 디렉터리는 임시 폴더로 두어 저장소 파일이나 개발 서버에 의존하는지 확인한다.

`desktop/tests/native_cycle.py`는 같은 방식으로 위 사이클 전체를 실제 앱에서 확인한다. 두 임시 프로젝트의 Claude 기록 수집→도구 메시지 제외와 반복 발견→검증용 CLI의 AI 분석(근거 없는 항목 제외 포함)→규칙 초안 노트→다른 프로젝트로 규칙 반영·저널 기록→학습 카드 상태→재시작 뒤 실적 기반 예상→정리서까지 7단계를 검사한다. `SILOLINK_DESKTOP_CONFIG_DIR`로 띄운 독립 프로필은 사용자가 실행 중인 SiloLink에 넘겨지지 않고 별도 인스턴스로 실행된다.

## 알려진 후속 범위

앱 데이터 JSON은 16 MiB 한도로 보호한다. 장기간의 대화·문맥을 별도 저장소로 분리하고 보관/내보내기 정책을 갖추는 작업은 남아 있다. 문서 전체 재조회 비용, 많은 프로젝트의 백그라운드 성능, 원문 기반 자동 웹 조사, AI 내부 실행/대기 계측, 개인 예측 보정, 다중 저장소 일괄 반영·팀 공유·macOS는 후속 검증/구현 범위다. 현재 버전의 오류·빈 상태를 샘플 데이터나 가짜 성공으로 채우지 않는다.
