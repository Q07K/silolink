SiloLink 새 프로젝트 인계

확인한 결과

인계 폴더 전체를 새 레포에 복사하고 시작 문구를 전달하면 논의를 이어갈 수 있습니다

  • 확정한 이름·사용자 의도·검토 제안·미검증 사항을 별도 문서로 구분했습니다.
  • 기존 조사와 검토 원문은 스냅샷으로 함께 보관해 요약에서 빠진 근거를 다시 읽을 수 있습니다.
  • 사용자가 관리하는 SSH·폴더별 권한·Git 원격은 변경하지 않았고 새 레포·제품 코드를 만들지 않았습니다.
다음 조치
  • 사용자가 준비한 새 레포에 이 폴더 전체를 docs/context/silolink/로 복사합니다. sources 폴더도 포함합니다.
  • 새 프로젝트의 새 채팅에 PROMPT.md의 시작 문구를 전달합니다. 다른 위치에 복사하면 그 문구의 경로를 조정합니다.

1. 남은 문제와 미확인 사항

항목상태와 근거다음 조치
장기 방향과 첫 버전의 구분미확인

데스크톱·CLI·플러그인 양방향 사용은 장기 구상입니다. 기술 스택·최소 범위·전체 구현 착수·기존 제품 채택은 미확정입니다.

새 채팅에서 우선 목적과 실제 작업 한 건의 최소 흐름부터 정합니다.
기존 도구의 실사용과 신규 개발 이득미확인

사용자는 유사 도구를 아직 사용하지 않았습니다. 앞선 조사는 공식 문서 중심이며 실제 품질·효과를 검증하지 않았습니다.

CONTEXT.md와 RESEARCH.md의 사실 경계를 유지합니다. 기존 제품으로 해결되지 않는 불편이라고 단정하지 않습니다.
레포 생성·원격 연결·제품 구현미실행

사용자가 SSH·권한별 관리 구성을 설명하고 레포 생성 대신 인계 정리를 요청했습니다. 새 프로젝트 위치·GitHub 소유자·공개 범위는 미정입니다.

레포와 작업 폴더는 사용자의 기존 관리 방식으로 준비한 후 문서만 복사합니다.

3. 이름과 제품 구상의 현재 상태

사용자는 SiloLink(사일로링크)를 선택했습니다. 분리된 도구의 정보 사일로를 연결한다는 의미입니다. Groundwork·Research Desk는 같은 구상의 과거 후보명입니다.

장기적으로 리서치·브레인스토밍·결정·개발 산출물을 프로젝트 단위로 관리하고, 데스크톱에서 코딩 에이전트를 이용하며 외부 에이전트에서도 기록을 저장·조회하는 방향입니다. 기능별 구현 순서는 정하지 않았습니다.

4. 기존 프로젝트 지침과 설정의 범위

  • 이 묶음은 제품 맥락 자료이며 test2의 AGENTS.md·보고서 생성 의무·전역 설정을 새 프로젝트로 자동 확대하지 않습니다.
  • 새 레포의 지침을 먼저 확인하고 필요한 운영 규칙을 그 프로젝트에서 별도로 정합니다.
  • 원문 스냅샷의 report-json·로컬 경로는 당시 기록입니다. 새 프로젝트에서 실행 가능한 설정으로 취급하지 않습니다.
  • 전체 대화가 자동 전달된다고 가정하지 않고 실제 제공한 파일을 읽어 이어갑니다.

5. 추가 근거와 상세 내역

보충 자료 1개 펼치기

저장과 검증 범위

Markdown과 HTML은 기존 보고서 템플릿을 사용합니다. 생성 일치·내부 파일 링크·원문 복사 지문·ZIP 항목을 확인하는 범위이며 새 화면·모바일·인쇄 렌더링은 확인하지 않습니다. 새 프로젝트에서 문서를 읽고 작업한 결과까지 검증한 것은 아닙니다.
