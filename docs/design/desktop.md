## 화면의 중심

평소 AI 사용에서 발견한 내용을 원문과 함께 살펴보고 조사·학습·대화·실제 문서 개선·다음 작업으로 이어간다. 메뉴는 세 그룹으로 나눈다. 고정된 작업 순서나 AI 도구의 역할을 강제하지 않는다.

| 그룹 | 메뉴 |
| --- | --- |
| 내 작업 | 요약, 대화, 작업·일정, 일간·주간 회고 |
| 지식 탐색 | 기록·문서, 사용 분석, 조사, 학습 |
| 프로젝트 실행 | 프로젝트, 변경안 검토 |

1차 디자인 코멘트에서 역할이 불명확하다고 지적한 상단 슬로건·로컬 작업 공간 표시와 하단 상태줄은 제거한다. 현재 위치·프로젝트 선택·알림·새로고침을 최상단 헤더 한 줄로 통합하며, 작업 중일 때만 진행 표시를 둔다. 개수 정보는 홈의 현황에서 확인한다.

대화의 전역 진입점은 사이드바 메뉴 하나로 두고, 새 대화는 대화 화면 안에서 시작한다. 설정은 아래쪽 아이콘 하나로 둔다. 접기 버튼은 로고나 경계 위에 띄우지 않고 사이드바 안의 메뉴 조작 행에 둔다. 72px 아이콘 탐색으로 전환해도 현재 메뉴와 프로젝트 선택을 유지한다. 메뉴명은 호버 또는 키보드 포커스 시 툴팁으로 표시하며 클릭·마우스 이탈·Escape로 닫는다. 툴팁은 탐색 영역의 스크롤에 잘리지 않는다. 현재 접힘 상태는 앱 창이 열려 있는 동안 유지한다.

상단 경로는 사이드바의 실제 메뉴 그룹과 현재 메뉴를 표시한다. ‘요약’을 모든 화면의 상위로 두지 않는다. ‘내 작업’은 요약, ‘지식 탐색’은 기록·문서, ‘프로젝트 실행’은 프로젝트 화면으로 이동하는 그룹 시작점이다. 현재 메뉴는 aria-current로 표시하고, 문서 읽기에서는 ‘지식 탐색 / 기록·문서 / 파일 경로’로 목록 복귀와 현재 문서를 구별한다. 설정은 그룹 경로를 만들지 않고 ‘설정’만 표시한다. 경로의 상위 조작과 현재 항목은 같은 14px 크기를 사용하며 색과 굵기로 역할을 구별한다.

설정 아이콘을 누르면 같은 사이드바에 AI 도구 / 화면 / 기록·수집 / 알림·회고 / 앱 관리만 표시한다. 본문은 선택한 분류의 제목과 설정에 사용한다. ‘작업 공간으로’는 설정을 열기 전 화면과 탭으로 돌아가며 프로젝트 선택과 사이드바 접힘 상태를 유지한다. 접힌 설정 메뉴도 아이콘과 툴팁을 제공한다. 분류 사이의 입력 초안은 유지하고 기존 설정 저장 명령으로 함께 반영한다. 수집 관련 화면과 회고 설정 링크는 해당 분류로 바로 연다.

AI 도구 카드 제목에 도구 이름과 로고를 나란히 놓고, 버튼에는 ‘연결’ 또는 ‘스킬 업데이트’를 쓴다. 로고는 로컬에 번들한다. [Codex 공식 VS Code 확장](https://marketplace.visualstudio.com/items?itemName=openai.chatgpt), [Claude Code 공식 VS Code 확장](https://marketplace.visualstudio.com/items?itemName=anthropic.claude-code), [Google Antigravity 보도자료 자산](https://antigravity.google/press).

홈은 ‘전체 프로젝트’ 제목 아래 전체 현황·프로젝트 표·진행 중 작업을 보여 준다. 반복 요청과 모호한 표현 분석은 사용 분석에서 다루며, 홈에 역할이 불명확한 분석 문구와 별도 AI 실행 행을 반복하지 않는다. 프로젝트 이름을 누르면 해당 프로젝트를 선택해 열며, 작업에는 프로젝트 이름을 함께 표시한다. 첫 사용은 짧은 빈 상태 안내와 프로젝트 연결 행동으로 시작한다. 별도의 네이비 온보딩 카드나 단계 소개를 두지 않는다. 밝음/어두움 테마를 지원하며 샘플 데이터를 실제 앱의 기본 데이터에 넣지 않는다.

대화는 질문 입력과 AI 도구 선택을 중심에 두고 문서·기록·다른 프로젝트 선택은 ‘자료 선택’을 열어 추가한다. 닫힌 상태에서도 선택한 자료 수를 표시한다. ‘문서 요약’은 최대 20개 문서와 질문을 채우는 예시이며 자동으로 전송하지 않는다. 사용자가 자료와 질문을 확인하고 ‘질문하기’를 눌러 실행한다. 기존 실패·취소·이전 대화·노트/작업 저장 경로를 유지한다. 실행 환경의 기술 설명은 기본 화면의 주된 안내로 사용하지 않는다.

## 브랜드와 공통 토큰

브라우저 검토판은 `npm run design`에서 [디자인 시스템](http://127.0.0.1:7431/design-system.html)으로 연다. 기본 기준은 글자·8px 간격·색, 공통 요소는 버튼·배지·입력과 하단 실행을 보여 준다. 상태는 버튼·입력·사이드바 항목·목록 행·배지·안내·탭·빈 상태·토스트·대화상자·팝오버·툴팁의 상태를 강제로 펼친 표로, 토큰은 `tokens.css`의 모든 토큰을 값과 견본으로 보여 준다. 두 탭은 같은 견본을 밝게/어둡게 영역에 나란히 칠한다(하위 영역에 `color-scheme`을 지정하면 `light-dark()` 토큰이 그 영역 기준으로 다시 계산된다). 화면 패턴은 설정 사이드바·목록·빈 상태 제안을 보여 준다. 예시 조작을 확인한 뒤 Annotate로 요소에 직접 의견을 남긴다. 실제 앱과 `tokens.css`, `app.css`, 공통 컴포넌트를 공유하며, 예시 입력은 파일에 저장되지 않는다. 호버·포커스·누름의 강제 표시는 공통 스타일의 `[data-state]` 선택자를 그대로 사용하므로 실제 상태와 어긋나지 않는다. 빈 상태 제안 등 검토판의 예시는 합의 후 제품 화면에 반영한다.

글자·간격·크기의 원본도 [tokens.css](../../desktop/src/styles/tokens.css)다. 화면마다 px 값을 추가하지 않고 공통 역할 토큰을 사용한다. 일반 UI와 사용자가 읽는 Markdown 본문은 같은 기본 글꼴을 쓰며, 문서의 제목 계층과 코드에는 해당 역할을 유지한다.

| 역할 | 공통 기준 |
| --- | --- |
| 본문·메뉴·경로·버튼·입력 | 14px, 본문 줄 높이 1.6, 컨트롤 줄 높이 20px |

| 섹션 사이 / 패널 안쪽 | 24px / 24px; 작은 화면도 패널 24px |

굵기는 400·500·600·700으로 제한한다. 제목 계층의 의미를 유지하면서 같은 종류의 제목은 같은 크기를 사용한다. 선택 상태를 글자 크기로 바꾸지 않는다. 미리보기의 검토용 도구줄은 보조 정보 크기를 사용한다. 체크박스 첫 줄 정렬의 4px 보정, 1px 경계·스크린리더 전용 숨김 등은 레이아웃 간격과 구별한다. 폰트·아이콘·모서리 크기는 간격 눈금에 맞춰 강제 변경하지 않는다. 4px(`--space-half`)는 배지·알림 개수 같은 인라인 세부에만 쓰고 레이아웃 간격에는 쓰지 않는다. 자간·고정폭 글꼴·그림자·z-index도 토큰으로 두며, 화면 CSS에 hex·px 값을 새로 쓰지 않는다. 기존 토큰 이름은 바꾸지 않고, 필요하면 `--shadow-panel`처럼 별칭을 추가한다.

### 창 외곽 (2026-11-09 결정: 외곽 프레임과 본문 카드)

외곽 시안 8개(외곽 프레임, 두 장의 카드, 한 장의 큰 카드, 반투명 외곽, 두 장의 카드 변형 4개)를 밝음/어두움 × 메뉴 펼침/접힘 네 화면씩 비교해 외곽 프레임과 본문 카드를 택했다.

- Windows 기본 제목 줄을 끄고(`decorations: false`) 앱 헤더가 제목 줄을 겸한다. 헤더 빈 곳을 끌면 창이 움직이고 두 번 누르면 최대화된다(`data-tauri-drag-region`). 버튼·선택 상자에는 이 속성을 달지 않는다.
- 최소화·최대화·닫기는 헤더 오른쪽 끝에 붙고 헤더 높이를 꽉 채운다. 최대화된 창에서는 '이전 크기로' 아이콘으로 바뀐다. 닫기에 마우스를 올리면 Windows 관례대로 빨간 면이 된다.
- 창 전체는 `--frame` 색이고 제목 줄과 메뉴는 경계선 없이 그 위에 놓인다. 페이지만 둥근 카드(`--background`, 12px, 1px 경계)로 오른쪽·아래 8px 띄워 둔다.
- 메뉴를 접고 펼칠 때 바뀌는 것은 메뉴 폭과 글자 표시뿐이다. 로고·메뉴 펼치기·메뉴 아이콘·설정 아이콘은 모두 20px이고 접힌 메뉴 폭(72px)의 가운데선에 놓여 펼쳐도 움직이지 않는다.
- 프로젝트 선택은 제목 줄 안에서 테두리 없이 글자와 화살표로 보이고, 마우스를 올리면 면이 생긴다.

### 상태 표현 (2026-11-07 결정: 부드러운 면 + 글로 포커스)

시안 A(현재 인상 유지)와 B(부드러운 면)를 밝음/어두움으로 비교해 B를 택했다.

| 요소 | 기본 | 호버 | 포커스 | 누름 | 비활성 / 처리 중 / 오류 |
| --- | --- | --- | --- | --- | --- |
| 주요 버튼 | Brand 600 채움 | `--accent-hover` | 표면색 간격 + 강조선 + 빛번짐 | `--accent-pressed` | 비활성: 옅은 면·보조 글자 / 처리 중: 색 유지, 스피너, `aria-busy`, 다시 누를 수 없음 |
| 보조·조용한 버튼 | 표면 + 3:1 경계 / 투명 | `--soft` | 강조선 + 빛번짐 | `--pressed` | 같음 |
| 위험 버튼 | 빨간 글자·테두리 | `--danger-soft` | 같음 | 같음 | 되돌릴 수 없는 확인에만 빨간 채움(`primary danger`) |
| 입력·선택 | `--field` 옅은 면 + 3:1 경계 | `--field-hover` | 표면색으로 돌아오며 강조 테두리 + 빛번짐 | — | 오류: `--danger-soft` 면·빨간 테두리·문구, 비활성: 옅은 면 |
| 사이드바 항목 | 보조 글자 | `--frame-hover` 면 + 진한 글자 | 안쪽 2px 강조선 | 선택 면 | 선택: 표면색으로 떠오름·1px 경계·강조 글자·굵기(왼쪽 선 없음) |
| 목록 행·알림 행 | 투명 | `--soft` | 안쪽 2px 강조선 | `--pressed` | 펼친 행은 `--soft` 유지 |

입력에서 경계선을 없애는 B 시안의 모습은 WCAG 조작 요소 대비(3:1)를 맞추지 못해, 옅은 면에 기존 `--control-border` 경계를 유지했다. 포커스는 `box-shadow` 링이므로 Windows 고대비 모드를 위해 투명 `outline`을 함께 둔다. 상태 색(성공·주의·오류·강조)은 옅은 배경(`*-soft`)과 같은 계열의 진한 글자를 쌍으로 쓰며 모든 쌍이 밝음/어두움에서 4.5:1 이상이다. 사이드바 호버 글자는 진한 글자로 바뀌어 대비를 확보한다.

떠 있는 요소는 같은 `--shadow-overlay`와 12px 모서리를 쓴다. 토스트는 오른쪽 아래에 쌓이고 성공·안내는 정해진 시간 뒤 닫힐 수 있지만, 오류는 `role="alert"`로 즉시 알리고 사용자가 닫을 때까지 남는다. 대화상자는 네이티브 `<dialog>`의 `showModal()`로 포커스를 가두고, Escape·바깥 클릭·닫기 버튼으로 닫으며, 닫히면 연 버튼으로 포커스를 돌려준다. 실행 버튼은 공통 Actions로 하단 오른쪽에 둔다.

공통 조작은 다음 기준을 사용한다.

- 대화 본문은 다른 화면과 같은 왼쪽 선과 폭을 사용한다.
- 알림은 벨 아래의 팝오버에서 읽는다. 본문을 밀지 않으며 바깥 클릭·Escape·닫기로 닫는다. Escape/닫기 후 벨로 포커스를 돌려준다.
- 탭은 44px 높이·선택 밑줄·충분한 글자 크기와 함께 tablist/tab/tabpanel 관계, aria-selected, 하나의 Tab 진입점, 좌우 방향키·Home·End 이동을 제공한다. 회고의 일간/주간도 같은 동작이다.
- 폼과 카드의 실행 버튼은 공통 Actions를 사용해 하단 오른쪽에 모은다. 주요 버튼은 묶음의 마지막에 둔다. 화면 전체 탐색은 헤더에, 입력칸이나 목록 행에 속한 조작은 대상 옆에 둔다.
- 실행 아이콘은 동작을 보강할 때 텍스트 앞에 한 개를 사용한다. 질문은 말풍선, 기록 가져오기는 내려받기, 자동 수집 설정은 타이머로 구분한다.
- 입력 폼은 공통 Field와 form-stack을 사용한다. 레이블과 컨트롤 사이는 8px, 필드 사이는 24px이며 레이블을 인라인 문장처럼 배치하지 않는다. 변경안 작성은 문서 선택/불러오기 → 본문 편집 → 정리 이유 → 하단 오른쪽 검토 순서다. 새 문서·JSON 작성과 실제 반영도 같은 필드·실행 영역 기준을 사용한다. 작성 내용이 바뀌면 이전 검토 결과를 무효화한다.
- 조사는 자료/조사 노트로 나누고, 자료와 노트의 상세는 목록에서 선택해 연다. 학습도 노트 목록에서 시작하며 추가 버튼으로 작성 폼을 연다. 내보내기는 요청했을 때만 선택 목록을 보이고 현재 노트 종류로 범위를 제한한다.
- 기본 화면의 내부 용어·일괄 경고·중복 안내를 줄인다. 원문 미확인 상태, 적용 조건과 실패 등 판단에 필요한 정보는 관련 자료나 실행 경로에서 유지한다.

동작은 [WAI-ARIA Tabs 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)과 [NN/g의 일관성·기존 관례·정보 최소화 원칙](https://www.nngroup.com/articles/ten-usability-heuristics/)을 참고한다. 오른쪽 실행 배치는 이 앱의 조작 규칙이며 모든 플랫폼에 대한 보편적 규칙을 주장하지 않는다.

실제 색의 원본은 [tokens.css](../../desktop/src/styles/tokens.css)다. 아래는 로고와 함께 쓰는 앱 UI용 팔레트이며 래스터 이미지의 모든 픽셀 색을 단일 값으로 바꾼다는 의미가 아니다.

상태는 색과 문구를 함께 사용한다. 주요 버튼의 흰 글씨는 Brand 600 위에 배치하고 Brand 400을 같은 용도로 대체하지 않는다. 네이비 발견 영역에서는 밝은 버튼과 짙은 글씨를 사용한다. 표면·본문·경계·강조 전경은 밝음/어두움의 의미 토큰으로 분리한다. 앱 설정의 시스템/밝음/어두움 테마를 적용한다.

본문은 로컬에 번들한 Pretendard Variable과 Windows 시스템 대체 글꼴을 사용한다. Windows 창·트레이·설치·제거 아이콘과 인앱 헤더는 제공된 `silolink-app-icon.png`의 같은 S 심볼을 사용한다. 인앱 로고 영역에는 원본 PNG와 SiloLink 이름만 한 줄로 표시하고 글자색이 밝은·어두운 테마에 맞춰 바뀐다. 헤더의 로고 영역과 사이드바는 같은 너비 변수를 사용하며, 펼친 상태의 로고는 메뉴 아이콘의 왼쪽 선에 맞추고 접힌 상태에서는 중앙에 둔다. 블루 팔레트는 버튼과 강조에 유지한다. Windows 아이콘은 Tauri 공식 아이콘 생성기로 변환한다.

Windows 프로세스 표시 이름은 앱·설치기 `SiloLink`, 동봉 CLI `SiloLink CLI`이며 같은 검정 바탕의 흰색 S 아이콘을 EXE 리소스에 포함한다. 앱은 시작 컨텍스트에 브랜드 PNG를 기본 창 아이콘으로 지정해 실제 창과 트레이에도 적용한다. CLI 리소스는 루트 `build.rs`에서 공개 `silolink` 실행 파일에만 연결한다. 공유 라이브러리나 검증용 공급자에 같은 리소스를 중복 연결하지 않는다.

## 설치 화면

설치 프로그램은 사용자가 선택한 **시네마틱 다크** 방향을 적용한다. 검정 사각형 바탕에 흰색 S가 들어간 `silolink-app-icon.png`를 주력으로 사용하며, 검정 심볼 단독이나 파란 심볼로 대체하지 않는다. 로고는 원근·두께·윤곽 조명·그림자가 있는 입체 블록으로 표현하고 평면 회전 이미지로 바꾸지 않는다. 일반 배율에서는 시안과 같은 660×606px 비율로 표시하고 중복 제목 표시줄을 없앤다. 설치 상태에 따라 설치·업데이트·재설치·구버전 차단 문구와 버튼을 바꾼다. 구현과 검증은 [배포 계약](../development/releasing.md#설치-exe의-화면과-버전-처리)을 참고한다. 앱 본문의 기존 블루 행동 색상 변경은 이 설치 화면 작업에 포함하지 않는다.

## 실제 공통 모듈

현재 표시·조작의 공통 컴포넌트는 Button, Badge, Heading, Tabs/TabSet, Actions, Field, DisclosureRow, Empty, NoProject, PromptButton, MarkdownContent와 Toast/ToastRegion, Dialog다. 공개 props는 추가만 한다: Button `danger`·`loading`, Badge `tone`의 `accent`·`warning`·`danger`, Field `hint`·`error`(레이블 이름과 분리해 `aria-describedby`·`aria-invalid`로 연결). Toast·Dialog는 상태 탭에서 시연하며 기능 화면이 필요해질 때 사용한다. [components.tsx](../../desktop/src/components.tsx)에서 실제 사용하는 요소만 관리한다. 이것은 코드 절감률이나 전체 UI의 재사용률 측정이 아니다. 이전의 가정상 6화면·22개 후보 집계는 구현 기준에서 제거했다.

- App: 앱 탐색·프로젝트 범위·알림·작업/오류 상태.
- Workspace context: 선택한 맥락·조회·실행 후 현재 상태 갱신.
- api: 네이티브 명령과 오류의 경계. 일반 앱 실행을 브라우저의 가짜 성공 응답으로 대체하지 않는다. 별도 `npm run design`은 표시된 예시 데이터로 같은 React 화면을 검토하며, 실제 저장·수집·AI 실행을 거절한다.
- 기능별 페이지: 분석/학습/회고, 프로젝트/문서, 조사/작업/설정/대화, 실제 변경 검토를 분리한다.
- Rust: 프로젝트 귀속·문서 범위·원문 revision·수집·저장·변경·복구의 권위. 화면에서 재구현하지 않는다.

## 검증 기준

새 프로젝트의 빈 상태부터 연결·수집·읽기·분석·학습·작업·변경·복구를 이어서 확인한다. 실제 외부 편집과 범위 밖 경로를 보존/거절하고, 재실행 후 설정·기록이 남는지 확인한다. 검증용 공급자의 프로세스 연결 확인을 실제 모델의 의미 분석 품질 검증으로 확대하지 않는다. 실행 근거와 남은 범위는 [테스트 사례](../../tests/CASE_MATRIX.md)에 관리한다.
