# SiloLink 데스크톱 디자인

- 기준일: 2026-11-02, Asia/Seoul.
- 사용자 선택: 최신 전체 경험 시안의 첫 번째 **발견에서 시작**을 기준으로 앱 구현. 이전 서재·작업대·컨트롤 룸 등의 방향은 채택하지 않았다.
- 브랜드 원본: `assets/branding/silolink-v1`. 제공한 PNG를 유지하고 앱에서 사용한다.
- 제품 범위: [PRD](../product/prd.md). 구현과 사용법: [데스크톱 계약](../development/desktop.md).

## 화면의 중심

평소 AI 사용에서 발견한 내용을 원문과 함께 살펴보고 조사·학습·대화·실제 문서 개선·다음 작업으로 이어간다. 메뉴는 요약, 사용 분석, 조사, 학습, 프로젝트, 작업·일정, 기록·문서이며 회고·알림 설정·대화·변경 검토는 관련 맥락에서 이어진다. 고정된 작업 순서나 AI 도구의 역할을 강제하지 않는다.

선택한 시안의 어두운 왼쪽 탐색, 밝은 작업 공간, 발견과 후속 작업의 배치를 유지한다. 이전 시안의 붉은 강조는 제공한 로고를 기준으로 블루 브랜드 체계로 교체했다. 샘플 프로젝트·예시 통계·고정 AI 응답을 실제 앱의 기본 데이터에 넣지 않는다.

## 브랜드와 공통 토큰

실제 색의 원본은 [tokens.css](../../desktop/src/styles/tokens.css)다. 아래는 로고와 함께 쓰는 앱 UI용 팔레트이며 래스터 이미지의 모든 픽셀 색을 단일 값으로 바꾼다는 의미가 아니다.

| 역할 | 값 | 사용 |
| --- | --- | --- |
| Brand 700 | `#0349C7` | 짙은 브랜드 블루 |
| Brand 600 | `#0058ED` | 밝은 테마의 주요 행동·선택·링크 |
| Brand 400 | `#218BF5` | 버튼·상태의 보조 강조 |
| Brand 200 | `#9DCCFF` | 어두운 테마의 강조 전경 |
| Brand 50 | `#EAF2FF` | 밝은 테마의 선택 배경 |
| 탐색 배경 | `#1D2431` | 밝은 테마에서도 유지하는 어두운 탐색 영역 |
| 기본 본문 | `#202530` | 밝은 테마의 주요 정보 |
| 보조 본문 | `#626C7E` | 출처·경로·시각·범위 |

상태는 색과 문구를 함께 사용한다. 주요 버튼의 흰 글씨는 Brand 600 위에 배치하고 Brand 400을 같은 용도로 대체하지 않는다. 표면·본문·경계·강조 전경은 밝음/어두움의 의미 토큰으로 분리한다. 앱 설정의 시스템/밝음/어두움 테마를 적용한다.

본문은 로컬에 번들한 Pretendard Variable과 Windows 시스템 대체 글꼴을 사용한다. Windows 창·트레이·설치·제거 아이콘과 인앱 헤더는 제공된 `silolink-app-icon.png`의 같은 S 심볼을 사용한다. 인앱에서는 원본 PNG와 별도 서비스명 텍스트를 배치하고 글자색이 밝은·어두운 테마에 맞춰 바뀐다. 헤더의 로고 영역과 사이드바는 같은 너비 변수를 사용하며, 로고는 메뉴 아이콘의 왼쪽 선에 맞춘다. 블루 팔레트는 버튼과 강조에 유지한다. Windows 아이콘은 Tauri 공식 아이콘 생성기로 변환한다.

Windows 프로세스 표시 이름은 앱·설치기 `SiloLink`, 동봉 CLI `SiloLink CLI`이며 같은 검정 바탕의 흰색 S 아이콘을 EXE 리소스에 포함한다. 앱은 시작 컨텍스트에 브랜드 PNG를 기본 창 아이콘으로 지정해 실제 창과 트레이에도 적용한다. CLI 리소스는 루트 `build.rs`에서 공개 `silolink` 실행 파일에만 연결한다. 공유 라이브러리나 검증용 공급자에 같은 리소스를 중복 연결하지 않는다.

## 설치 화면

설치 프로그램은 사용자가 선택한 **시네마틱 다크** 방향을 적용한다. 검정 사각형 바탕에 흰색 S가 들어간 `silolink-app-icon.png`를 주력으로 사용하며, 검정 심볼 단독이나 파란 심볼로 대체하지 않는다. 로고는 원근·두께·윤곽 조명·그림자가 있는 입체 블록으로 표현하고 평면 회전 이미지로 바꾸지 않는다. 일반 배율에서는 시안과 같은 660×606px 비율로 표시하고 중복 제목 표시줄을 없앤다. 설치 상태에 따라 설치·업데이트·재설치·구버전 차단 문구와 버튼을 바꾼다. 구현과 검증은 [배포 계약](../development/releasing.md#설치-exe의-화면과-버전-처리)을 참고한다. 앱 본문의 기존 블루 행동 색상 변경은 이 설치 화면 작업에 포함하지 않는다.

## 실제 공통 모듈

현재 표시·조작의 공통 컴포넌트는 Button, Badge, Heading, Tabs, Empty, NoProject, PromptButton, MarkdownContent 8종이다. [components.tsx](../../desktop/src/components.tsx)에서 실제 사용하는 요소만 관리한다. 이것은 코드 절감률이나 전체 UI의 재사용률 측정이 아니다. 이전의 가정상 6화면·22개 후보 집계는 구현 기준에서 제거했다.

- App: 앱 탐색·프로젝트 범위·알림·작업/오류 상태.
- Workspace context: 선택한 맥락·조회·실행 후 현재 상태 갱신.
- api: 네이티브 명령과 오류의 경계. 브라우저에서 가짜 성공 응답으로 대체하지 않는다.
- 기능별 페이지: 분석/학습/회고, 프로젝트/문서, 조사/작업/설정/대화, 실제 변경 검토를 분리한다.
- Rust: 프로젝트 귀속·문서 범위·원문 revision·수집·저장·변경·복구의 권위. 화면에서 재구현하지 않는다.

## 검증 기준

새 프로젝트의 빈 상태부터 연결·수집·읽기·분석·학습·작업·변경·복구를 이어서 확인한다. 실제 외부 편집과 범위 밖 경로를 보존/거절하고, 재실행 후 설정·기록이 남는지 확인한다. 검증용 공급자의 프로세스 연결 확인을 실제 모델의 의미 분석 품질 검증으로 확대하지 않는다. 실행 근거와 남은 범위는 [테스트 사례](../../tests/CASE_MATRIX.md)에 관리한다.
