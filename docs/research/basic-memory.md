- 조사·통합일: 2026-11-01, Asia/Seoul
- 범위: Basic Memory의 문서·검색·편집·검토 기능과 SiloLink의 지원 경험을 비교한다.

- 상태: 설치·실사용·검색 품질·편집 충돌·한국어 지원 검증 전. 아래 검증 가설은 재현한 결함이 아니다.

## 1. 비교의 출발점

같은 Markdown을 사람과 AI가 사용하면 사람이 내용을 확인·편집·이동할 수 있다. 사람이 편한 관리 경험과 AI의 정확한 문맥 이해를 위해서는 검색·구조·검토 과정도 살펴봐야 한다.

Basic Memory의 당시 공식 설명에는 웹 편집·위키·시각화·변경 제안·승인·이력이 포함됐다. 단순 파일 저장소나 사람용 화면이 없는 기억 도구로 비교하면 부정확하다. 로컬 기능과 Cloud 추가 기능, 문서상의 지원과 실제 사용성도 구별한다. [S1, S2, S6]

## 3. 실사용으로 확인할 쟁점

### 설명문과 구조화 기록의 일관성

일반 Markdown을 저장하고 AI가 관찰·관계 문법을 작성할 수 있다. 사용자가 항상 문법을 직접 쓰는 구조는 아니다. 다만 ADR 예시는 제목·문단만으로 스키마를 충족하지 않고 별도 관찰 항목이 필요하다고 설명했다. [S2, S3, S5]

결론 수정 시 설명문·관찰·관계가 함께 갱신되는지, 중복 표현과 불일치를 고치는 수고가 얼마나 드는지 확인해야 한다.

### 검색 시 주장과 조건의 동반 전달

관찰 검색과 관계 기반 문맥 구성을 사용한다. ‘소규모 시험에서 편했다’는 주장을 재사용할 때 ‘운영 환경 성능 미확인’이라는 조건이 함께 전달되는지 확인할 필요가 있다. 이 예시는 가상의 위험 설명이며 실제 오류 재현이 아니다. [S3]

검색된 주장에 버전·환경·적용 조건·미확인 사항이 붙는지, 원문 근거 위치로 돌아갈 수 있는지가 비교 기준이다. 이는 모든 요약·검색 시스템에 적용할 수 있는 질문이다.

### 형식 검증과 판단 상태

스키마 충족만으로 제안·확정 구분, 근거의 충분성, 이전 결론을 대체하는지의 판단이 해결되지는 않는다. [S4] 스키마·스킬·검토 기능으로 사람이 확인할 항목을 충분히 드러낼 수 있는지 비교해야 한다.

### 문서 연결에서 사고·실행 지원까지

SiloLink는 기록을 읽으며 대안을 탐색·비교·선택하고 개발로 이어가는 경험을 지원한다. Basic Memory에도 관계·시각화·검토가 있으므로 기존 템플릿·스킬·화면 설정으로 어디까지 가능한지 확인할 필요가 있다. [S1]

사람이 분류·연결·상태 변경을 유지하는 수고, 다음 작업에서 재사용하는 편의, 자유로운 탐색과 수정의 흐름을 비교한다. 특정한 분기·선택 순서를 모든 사용자에게 요구하는 것은 아니다.

## 4. 제품 개발에 주는 의미

[현재 제품 정의](../product/definition.md)는 CLI·플러그인·데스크톱을 통한 사용 맥락 분석·학습·조사·규칙 관리·플래닝을 지향한다. Basic Memory 비교는 이 목표의 구현·재사용 범위를 판단할 자료다.

| 선택지 | 적절할 수 있는 조건 | 감당할 일 |
| --- | --- | --- |
| 기존 도구와 편집 환경 활용 | 저장·검색·검토·재사용이 충분히 편함 | 설정과 기록 규칙 정착 |
| 기존 기반에 템플릿·스킬·화면 확장 | 특정 탐색·정리 단계에서 불편이 반복됨 | 인터페이스·형식 변화 대응 |
| 독립 작업 공간 구현 | 원하는 연결 경험의 이익이 유지 부담보다 큼 | 저장·검색·편집·복구와 공급자별 연결부 유지 |

실제 기술 선택 문서에서 근거와 조건을 보존하고, 대안을 탐색해 선택 이유를 남기고, 다음 AI 작업에 재사용하는 비교를 제안한다. 관찰할 것은 맥락·판단 상태 보존, 수동 편집과 재작업 부담, 실제 재사용과 자발적인 반복 사용이다. 이는 선택 가능한 평가 방법이며 고정된 제품 절차나 개발 착수의 의무 조건이 아니다.

Markdown 공유나 여러 AI 연결만으로 차별성·수요·생산성 향상이 입증되지는 않았다. 시간 절감·한국어 검색 정확도·구매 의향도 측정하지 않았다.
