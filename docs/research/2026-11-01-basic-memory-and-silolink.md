# Basic Memory의 사람·AI 공동 문서 관리와 SiloLink의 검증 과제

- 조사일: 2026-11-01, Asia/Seoul
- 질문: 사람과 AI가 같은 Markdown을 사용하면 사람에게 최적화된 문서 관리가 되는가? 어떤 아쉬움이 남고, SiloLink는 무엇을 검증해야 하는가?
- 범위: Basic Memory의 문서 구조·검색·공동 편집과 SiloLink의 리서치·아이디어 발전 흐름을 비교한다.
- 방법: 대화에서 확인한 공식 제품 페이지·문서·변경 이력을 정리했다. 설치·로그인·실사용·검색 품질 측정은 수행하지 않았다.
- 상태: 공식 자료 기반 1차 분석. 아래 한계는 재현한 결함 목록이 아니라 구조상 긴장과 실사용 검증 가설이다.

## 1. 결론

**사람과 AI가 같은 Markdown을 사용한다는 것은 사람이 내용을 직접 확인·편집·이동할 수 있다는 장점이다. 사람에게 가장 편한 문서 관리나, AI가 사람과 같은 맥락을 이해한다는 것까지 보장하지는 않는다.**

Basic Memory는 Markdown 원본에 관찰 항목·관계·검색 색인을 더해 사람과 AI가 지식을 함께 축적하고 재사용하도록 한다. 현재 공식 설명에는 웹 편집·위키·시각화·변경 제안과 승인·버전 이력도 포함돼 있다. 따라서 이를 단순한 파일 저장소나 사람이 읽는 화면이 없는 AI 기억 도구로 평가하면 비교가 부정확해진다. [S1, S2, S6]

SiloLink에서 검증할 후보는 **조사 문서를 읽고 대안을 확장·비교·선택한 다음 실행 과제로 나누어 다음 개발 작업에 전달하는 과정**이다. Basic Memory의 기존 기능·템플릿·스킬로 이 과정을 얼마나 편하게 수행할 수 있는지 확인해야 한다. 경쟁 제품에 없는 기능이라고 확정한 것은 아니다.

## 2. 대화에서 구체화한 SiloLink 방향

다음은 사용자가 설명한 제품 방향이다. 전체 기능의 첫 버전 구현이나 기술 스택을 확정한 기록은 아니다.

| 구성 | 의도한 역할 |
| --- | --- |
| 데스크톱 앱 | 사용자 PC의 프로젝트·파일·AI CLI를 연결하는 실행 환경 |
| 앱 안의 웹 기반 작업 화면 | 문서 열람·편집, 브레인스토밍, 아이디어 확장·분해 |
| 외부 AI CLI 연결부 | 사용자가 설치·로그인한 AI CLI로 작업 실행·문맥 전달·결과 수신 |
| SiloLink 자체 CLI | 외부 코딩 프로젝트와 에이전트에서도 기록 저장·검색·조회 |
| 공통 기록 기능 | 프로젝트별 문서·아이디어·결정·관계·검토 상태 관리 |

비용 설계의 목표는 사용자의 기존 AI 구독과 CLI 이용 환경을 활용하는 것이다. 모든 공급자의 구독이 같은 CLI 기능·한도를 제공하거나 모든 앱 통합 방식에 적용된다는 확인은 아니다. 제공자별 이용 범위와 실제 실행은 별도 검증 대상이다.

개인 생산성·학습·외부 사용자용 제품 중 우선 목적과 수요는 본 조사 당시 미정이었다. 후속 대상 사용자와 제품 요구는 [제품 인터뷰 정리](../product/2026-11-01-product-interview.md)를 참고한다. 앞선 인계 자료의 기본 맥락은 [CONTEXT.md](../context/silolink/CONTEXT.md)를 참고한다.

## 4. 남는 아쉬움과 검증 가설

### 4.1 자연스러운 설명문과 구조화된 기록을 함께 유지하는 부담

Basic Memory는 일반 Markdown을 저장하고, AI가 관찰·관계 문법을 작성하도록 지원한다. 사용자가 항상 문법을 직접 작성해야 하는 구조는 아니다. [S2, S3]

다만 공식 ADR 예시에서는 제목과 문단만으로 스키마 필드를 충족하지 않고 해당 관찰 항목이 필요하다고 설명한다. [S5] 사람이 읽기 좋은 설명문과 검색·검증용 구조를 함께 관리할 때 내용이 중복되거나 서로 어긋나는지 확인할 필요가 있다.

**검증 질문:** 결론을 수정했을 때 설명문·관찰 항목·관계가 함께 갱신되는가? 사용자는 그 일관성을 유지하기 위해 얼마나 개입하는가?

### 4.2 같은 원본을 사용해도 검색 과정에서 조건이 빠질 가능성

Basic Memory는 개별 관찰을 검색하고 관계를 따라 문맥을 구성한다. [S3] 다음은 위험을 설명하기 위한 가상 기록이며 실제 오류 재현 결과가 아니다.

> 소규모 시험에서는 A가 편했다. 운영 환경의 성능은 아직 확인하지 않았다.

원본에 두 문장이 모두 있어도 재사용 시 첫 주장만 전달되면 적용 조건과 미검증 상태가 빠질 수 있다. 이는 Markdown 자체의 결함이나 Basic Memory에만 있는 문제라고 단정할 수 없다.

**검증 질문:** 검색된 주장에 대상 버전·환경·조건·미확인 사항이 함께 전달되는가? 사용자가 근거 위치로 돌아가 확인할 수 있는가?

### 4.3 형식 검증과 판단의 신뢰도 사이의 간격

스키마는 필요한 관찰·관계·메타데이터가 있는지, 값이 정한 형식에 맞는지 확인하는 데 도움이 된다. [S4] 하지만 필드가 채워졌다는 사실만으로 다음 판단이 해결되지는 않는다.

- 브레인스토밍에서 나온 제안을 확정 결정으로 기록했는가?
- 결론의 근거가 충분하고 현재 환경에도 적용되는가?
- 새로운 결론이 이전 결론을 대체한 것인지 다른 조건의 대안인지 명확한가?

**검증 질문:** 사람이 검토해야 할 주장과 상태 변경을 쉽게 찾고 판단할 수 있는가? 스키마·스킬·검토 기능으로 필요한 절차를 충분히 만들 수 있는가?

### 4.4 연결된 노트에서 생각을 발전시키는 작업으로 이어지는 부담

SiloLink에서 원하는 흐름은 문제 발견 → 대안 분기 → 비교 → 일부 보류 → 선택 → 하위 과제 분해 → 개발 전달이다. 노트와 관계 링크로 표현할 수 있고, Basic Memory에도 시각화와 검토 기능이 있다. [S1]

다만 사람이 매번 분류·연결·상태 변경 방식을 생각해야 한다면 기록 관리가 추가 업무가 될 수 있다. 현재 자료만으로 이 부담이 실제로 크거나 작다고 판단하지 않는다.

**검증 질문:** 실제 문서로 이 흐름을 수행할 때 어디에서 작업이 끊기는가? 그 불편이 기존 템플릿·스킬·화면 설정으로 해결되는가?

## 5. SiloLink의 개발 필요성과 선택지

다음은 조사자의 제안이며 사용자 결정이 아니다. 기존 구독 활용은 비용 설계의 목표이고, 다른 사람이 반복 사용하거나 전환할 이유는 별도로 검증해야 한다.

| 선택지 | 적절한 조건 | 추가로 감당할 일 |
| --- | --- | --- |
| Basic Memory와 기존 편집 환경 활용 | 기록 저장·검색·검토·다음 세션 재사용이 충분히 편함 | 초기 설정과 기록 규칙 정착 |
| 기존 기록 기반에 템플릿·스킬·전용 화면 추가 | 일부 사고·정리 단계에서만 반복 불편이 남음 | 기존 인터페이스와 형식의 변화 대응 |
| SiloLink의 독립된 데스크톱 작업 공간 개발 | 핵심 작업 흐름에 기존 구성으로 해결하기 어려운 불편이 반복됨 | 저장·검색·편집·복구와 공급자별 연결부 유지보수 |

현재 권고는 실제 흐름을 비교하고 불편이 남는 부분을 좁히는 것이다. 독립 앱·기존 제품 채택·확장 중 어느 것도 확정하지 않았다. Markdown 공유나 여러 AI 연결만으로 차별성이 입증된 상태는 아니다.

## 6. 최소 비교 실험 제안

실제 프로젝트의 기술 선택 문서 한 건으로 다음 작업을 수행한다. 아직 실행하지 않은 제안이다.

1. 기존 조사 문서에서 질문이나 문단을 선택한다.
2. AI와 대안 세 개를 만들고 조건·근거·미확인 사항을 비교한다. 세 개는 제안하는 시험 입력 수다.
3. 하나를 선택하고, 보류한 대안과 선택 이유를 함께 기록한다.
4. 선택을 실행 과제로 분해한다.
5. 다음 코딩 세션에서 기록을 조회해 실제 작업에 사용한다.

먼저 기존 도구에서 수행해 기준을 확보한다. 해결되지 않는 반복 불편이 확인되고 시제품 구현을 별도로 요청받으면 그 단계만 구현해 같은 작업으로 비교한다.

| 관찰할 것 | 확인할 증거 |
| --- | --- |
| 맥락 보존 | 주장과 근거·조건·미확인 사항이 다음 세션까지 유지되는가 |
| 판단 구분 | 아이디어·선택·보류·확정 상태를 사람과 AI가 혼동하지 않는가 |
| 편집 부담 | 연결·분류·수정에 필요한 수동 단계와 재작업 |
| 실제 재사용 | 저장한 결과가 다음 개발의 판단이나 실행에 쓰이는가 |
| 반복 사용 | 시연 이후 자신의 다음 작업에서 자발적으로 다시 사용하는가 |

공식 기능표나 긍정적인 반응만으로 생산성 향상·수요를 판정하지 않는다. 시간 절약·사용자 수·검색 정확도·지불 의향은 아직 측정하지 않았다.
