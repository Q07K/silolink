# SiloLink 설치와 첫 사용

SiloLink는 AI와 작업하던 폴더의 문서를 살펴보고, 이전 대화와 판단 근거를 다음 작업에서도 활용하도록 돕습니다. 처음에는 폴더 하나만 연결해 보세요.

Windows x64용입니다. GitHub 저장소의 **Releases**에서 **SiloLink-Setup-…-windows-x64.exe**를 받아 설치합니다. 릴리스가 아직 없다면 자동 배포의 첫 실행 전 단계입니다. 제공받은 체험 설치 파일도 사용할 수 있습니다. 설치 파일을 직접 만드는 방법은 [개발 안내](../development/releasing.md)에 별도로 있습니다.

이미 설치했다면 새 버전의 설치 EXE를 실행하세요. **업데이트 시작** 화면에 현재 버전과 새 버전이 표시되며 기존 설치 위치, 프로젝트, 기록과 설정을 이어서 사용합니다. 같은 버전은 **다시 설치**, 더 오래된 설치 파일은 **더 최신 버전을 사용 중입니다**로 안내합니다. 실행 중인 SiloLink가 있으면 종료 확인 후 진행합니다.

## 앱에서 AI 도구에 연결하기

1. 설치한 SiloLink를 열고 첫 화면의 **AI 도구 연결**을 누릅니다. 이미 프로젝트를 연결했다면 왼쪽 **알림·설정** 맨 위에 같은 기능이 있습니다.
2. 사용하는 도구의 **Codex에 연결**, **Claude Code에 연결**, **Antigravity에 연결** 버튼을 누릅니다. 여러 도구를 연결할 수 있습니다.
3. **연결됨**을 확인합니다. 이는 해당 도구의 사용자 스킬 폴더에 SiloLink를 등록했다는 뜻입니다. 도구 설치·로그인 상태는 별도로 확인해야 합니다.
4. 해당 AI 도구를 다시 열고, 작업할 프로젝트의 새 채팅에서 **silolink-init · 프로젝트 연결**을 선택합니다. 기본으로 들어간 요청을 보내거나 **“이 프로젝트를 연결하고 문서 현황을 알려줘”**라고 요청하세요. Codex에서는 `$silolink-init`, Claude Code·지원되는 Antigravity 화면에서는 `/silolink-init`으로 선택할 수 있습니다.

예전에 통합 스킬만 설치했다면 앱에 **기능별 스킬 추가 가능**이 표시됩니다. **Codex 스킬 업데이트** 같은 버튼을 누르면 기존 파일을 유지하며 새 선택 항목을 추가합니다.

`silolink-init`이 성공하면 SiloLink 앱의 **프로젝트** 목록에도 같은 폴더가 자동으로 추가됩니다. 앱을 켜 두었다면 몇 초 안에 반영되고, 꺼 두었다면 다음 실행 때 나타납니다. 기존 선택 프로젝트는 유지되므로 오른쪽 위 프로젝트 선택에서 새 폴더를 고르세요. 문서는 바로 확인할 수 있고, AI 대화 기록 가져오기는 별도 설정입니다.

## 기능별 선택 항목

Codex에서 `$silo`를 입력하면 다음 기능이 각각 보입니다. `init` 같은 명령을 직접 외우지 않고 한국어 설명을 보고 선택할 수 있습니다.

| 스킬 이름 | 할 수 있는 일 |
| --- | --- |
| `silolink-init` | 프로젝트 연결과 첫 문서 확인 |
| `silolink-docs` | 문서 현황·정리 후보 확인 |
| `silolink-docs-check` | 문서 변경안 미리보기 |
| `silolink-docs-apply` | 검토한 문서 변경 적용 |
| `silolink-docs-changes` | 문서 변경 이력 보기 |
| `silolink-docs-undo` | 선택한 문서 변경 복구 |
| `silolink-history` | AI 도구의 대화 기록 조회 |
| `silolink-sync` | AI 기록 가져와 저장하기 |
| `silolink-records` | 이미 저장한 기록 보기 |
| `silolink-watch` | AI 기록 주기 수집 |

기존 `silolink` 통합 스킬과 `$silolink init` 같은 요청도 유지됩니다. 도구별 입력 표시는 다를 수 있습니다. 문서 적용·복구는 구체적인 변경안과 사용자의 요청 범위를 확인한 뒤 진행합니다.

설치 파일에 SiloLink 실행 파일이 포함되어 있어 Rust·Node·npm 설치나 PATH 설정이 필요하지 않습니다. 사용하는 AI 도구 자체는 먼저 설치하고 로그인해 주세요. Antigravity는 스킬 파일 등록을 지원하며 해당 앱에서의 발견·실행은 별도 검증 대상입니다.

## Codex 플러그인으로 관리하기 — 선택 사항

앱의 스킬 연결 대신 Codex 플러그인 설정에서 관리하려는 경우에 선택합니다. 두 방식을 동시에 설치하면 같은 스킬이 두 번 보일 수 있으므로 하나를 선택하세요.

1. 체험 ZIP을 계속 보관할 폴더에 **모두 압축 해제**합니다. ZIP 안에서 바로 실행하지 마세요.
2. **시작 안내.html**을 열어 안내를 읽고, 같은 폴더의 **Codex에 등록.cmd**를 두 번 클릭합니다. 잠시 명령 창이 열려 Codex의 설치 목록에 SiloLink를 등록합니다. 직접 명령어를 입력할 필요는 없습니다.
3. 등록 성공을 확인한 뒤 Codex를 완전히 종료하고 다시 엽니다.
4. **설정 → 플러그인 → 디렉터리 찾아보기**에서 **SiloLink 체험**을 선택해 SiloLink를 설치합니다. 이 단계는 공개 디렉터리가 아닌 이 PC의 체험 목록을 사용합니다.
5. AI와 작업하던 프로젝트의 새 채팅에서 `$silolink-init`을 선택하고 **“이 프로젝트를 연결하고 문서 현황을 알려줘”**라고 요청합니다. 작업 폴더가 정해져 있지 않으면 사용할 폴더를 알려주세요.

문서 개수와 정리 후보, 확인하지 못한 범위를 안내받으면 첫 연결이 끝난 것입니다. “이 후보의 원문을 읽고 어떻게 정리하면 좋을지 제안해줘”라고 이어갈 수 있습니다. 문서가 없는 폴더도 연결할 수 있습니다.

플러그인에 SiloLink 실행 파일이 포함됩니다. Rust·Node·npm을 설치하거나 PATH를 설정할 필요는 없습니다. 등록한 원본 폴더는 이후 재설치에 쓰이므로 보관하세요. 옮겼다면 새 위치에서 등록 파일을 다시 실행합니다.

## SiloLink 앱에서 시작하기

1. 설치한 SiloLink를 엽니다. AI 도구 연결 전에도 앱에서 문서부터 살펴볼 수 있습니다.
2. **프로젝트 연결 → 폴더 선택**에서 AI와 작업하던 폴더를 고릅니다.
3. **선택한 프로젝트 연결**을 누릅니다. 연결 안내를 읽으면 별도 초기화 명령 없이 시작할 수 있습니다.
4. **첫 문서 확인** 화면에서 문서 개수와 정리 후보를 확인하고 **문서 …개 살펴보기**로 원문을 읽습니다. 문서가 없거나 일부를 읽지 못한 경우에는 그 상태를 안내합니다.

기록·문서, 노트, 대화에서는 Markdown 표·체크 목록·취소선·각주를 표시합니다. 넓은 표와 긴 코드는 해당 영역 안에서 가로로 스크롤할 수 있습니다. 체크 목록은 원문에 적힌 완료 상태를 보여 주며 읽는 화면에서 파일을 수정하지 않습니다.

목차의 제목 링크나 각주 번호를 누르면 본문 안의 해당 위치로 이동합니다. 다른 프로젝트 문서의 제목을 가리키는 링크도 그 문서를 연 뒤 지정된 제목으로 이동합니다.

AI 대화 기록도 보고 싶다면 **AI 기록 가져오기 설정**으로 이동해 이 PC의 보관 폴더를 선택하고 가져오기를 실행하세요. 문서를 먼저 살펴보는 데에는 이 설정이 필요하지 않습니다. Codex와 Claude Code의 지원되는 로컬 기록을 대상으로 하며 도구별 성공·누락·실패를 확인해야 합니다. 앱에서 AI에게 질문하려면 선택한 공식 Codex 또는 Claude Code 실행 도구와 로그인이 필요합니다.

## 내 문서와 AI는 어떻게 바뀌나요?

폴더를 연결하면 그 안에 `.silolink` 관리 정보를 만듭니다. 기존 문서 내용은 유지됩니다. 첫 확인은 Markdown(`.md`) 문서를 대상으로 하며 Word·PDF 문서는 아직 읽지 않습니다. 제외 규칙과 읽기 제한 때문에 일부 문서는 결과에 없을 수 있습니다.

실제 문서 수정은 변경할 내용과 영향을 확인하는 별도 단계입니다. AI 기록을 가져오는 것도 별도 선택이며, 모든 대화가 자동으로 수집되는 것은 아닙니다. 가져온 기록과 문서 변경 전 백업은 선택한 저장 폴더에 보관합니다.

SiloLink가 AI 모델을 자동으로 학습시키거나 모든 AI 도구에 내용을 자동 전달하지는 않습니다. 문서·기록을 근거로 질문하거나 다음 작업에 사용할 맥락을 정리할 때 도움을 받는 방식입니다. AI에게 자료를 포함해 질문하면 해당 AI 서비스가 그 내용을 처리합니다.

## 막혔을 때

| 보이는 상태 | 다음 행동 |
| --- | --- |
| 스킬로 연결했지만 앱에는 이전 프로젝트만 보임 | 이 자동 연결 수정이 포함된 최신 설치 파일로 앱을 업데이트한 뒤 해당 폴더에서 `silolink-init`을 한 번 더 실행하세요. 기존 문서와 프로젝트 식별자는 유지됩니다. 계속 안 보이면 앱의 새로고침과 연결 오류 안내를 확인하세요. |
| 기존 스킬 확인 필요 | 표시된 폴더에 수정한 스킬이나 다른 설치 정보가 있습니다. 내용을 확인·백업한 뒤 교체 여부를 판단하세요. 기존 파일은 자동 덮어쓰지 않습니다. |
| 앱에 포함된 실행 파일을 찾지 못함 | 최신 설치 파일로 SiloLink를 다시 설치하세요. 앱 EXE만 다른 폴더로 옮기면 함께 설치된 파일을 찾지 못할 수 있습니다. |
| 앱에서 연결했지만 도구에 스킬이 안 보임 | 해당 도구를 완전히 종료했다가 다시 열고, 새 프로젝트 채팅에서 SiloLink를 선택하세요. |
| 등록 창에서 Codex를 찾지 못함 | Codex 데스크톱 앱 설치를 먼저 확인합니다. 등록 파일은 PATH와 기본 Windows 설치 위치를 확인합니다. 다른 위치에 설치했다면 현재는 개발자의 연결 도움이 필요합니다. |
| SiloLink 체험 목록이 안 보임 | 등록 창의 성공 여부를 확인하고 Codex를 완전히 종료했다가 다시 엽니다. 로컬 플러그인 기능을 지원하는 최신 버전인지 확인합니다. |
| 목록은 있지만 채팅에서 스킬이 안 보임 | SiloLink를 설치·활성화한 뒤 새 프로젝트 채팅을 엽니다. |
| 지원하는 문서가 0개 | `.md` 문서가 있는 폴더인지 확인합니다. 문서가 없는 폴더라면 AI 기록 가져오기로 시작할 수 있습니다. |
| 폴더는 연결했지만 문서 확인 실패 | ‘문서 다시 확인’을 누르고 폴더 접근 상태와 표시된 오류를 확인합니다. 읽기 실패를 문서 없음으로 취급하지 않습니다. |
| AI 질문에 응답하지 않음 | 선택한 공식 AI 도구의 설치·로그인과 표시된 오류를 확인합니다. 구독·이용 한도는 해당 서비스의 조건을 따릅니다. |

플러그인 제거는 Codex의 플러그인 설정에서 진행합니다. 앱이나 플러그인을 제거해도 프로젝트 문서와 따로 저장한 기록은 자동 삭제되지 않습니다. 사용자 스킬 폴더에 등록한 파일도 앱 제거와 별도로 남을 수 있습니다. 자동 업데이트는 아직 제공하지 않습니다. 코드 서명은 SignPath Foundation 승인 후 배포하는 파일부터 적용되며, 서명된 파일은 **속성 → 디지털 서명**에서 확인할 수 있습니다. 자세한 내용은 [Code signing policy](../../CODE_SIGNING.md)를 참고하세요.
